    <h2>Overview</h2>
    <p>
      A penetration test report is a document written after security testers look for weaknesses in a company’s websites, systems, or network. It explains what they found, why it matters, and what should be fixed. Some parts of the report are written for technical readers who fix security problems, while other parts are written for people who need to understand the business impact.
    </p>
    <p>
      The purpose of this evaluation is to see whether the glossary makes these reports easier to understand. Participants will read part of a report and answer questions before and after using the glossary. The goal is to measure whether the glossary helps readers better understand security terms, attack scenarios, risk, and recommended fixes.
    </p>
    <p>
      You can choose which user study to participate in based on the descriptions below. Feel free to participate in both if you would like.
    </p>
  </div>

  <div class="evaluation-card-grid">
    <section class="evaluation-card">
      <h2>Technical User Study</h2>
      <p>
        The technical user study is for those who find themselves to be the direct audience of detailed penetration test findings. This would include security professionals, software engineers, and system administrators who may be responsible for fixing the identified issues. If you find yourself likely to work through the technical walkthrough of a penetration test report, including the step-by-step description of how access was gained and how the attack progressed, this would be the study to participate in.
      </p>
      <a class="evaluation-button" href="{{ '/glossary/evaluation/technical/' | relative_url }}">
        Go to Technical Study
      </a>
    </section>
    <section class="evaluation-card">
      <h2>Non-Technical User Study</h2>
      <p>
        The non-technical user study is for everyone else. This includes business stakeholders, project managers, executives, and technical professionals who are not part of the primary audience of a detailed penetration test walkthrough. Even if you have a technical background, this study is likely the better fit unless you are the one who would directly implement the fix for the security issues described in a penetration test report.
      </p>
